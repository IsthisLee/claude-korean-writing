# 압축본 상시 주입 실험 보고 (2026-09-10)

## 한 줄 결론

압축본 상시 주입은 효과가 있었다. 채택을 권고한다.

블라인드 쌍대 판정 24쌍에서 B(주입) 21승, 무승부 3, A(기준) 0승. 12개 프롬프트 전부에서 B 가 이기거나 비겼다. 사전 등록한 주 기준 P1(승률 65%)과 보호 기준 G1~G5 를 모두 통과했다. 비용은 세션당 587 토큰이며, 캐시에 올라가므로 턴마다 다시 내지 않는다.

다만 붙일 것이 둘 있다. 압축본이 해라체로 쓰여 있어 답변 문체가 해라체로 기운다. `높임은 사용자 말투를 따른다` 한 줄을 넣고 다시 확인해야 한다. 남은 하나는 검사기 쪽이다. 정규식 훅은 채팅 답변에서 A 표본당 0.21건만 잡아 이것으로는 답변 품질의 회귀를 감시하지 못한다.

## 무엇을 시험했나

SessionStart 훅으로 587 토큰짜리 압축 규칙(inject.md v3)을 넣으면, 스킬이 뜨지 않는 보통의 채팅 답변에서 한국어가 더 자연스러워지는지. 기준은 실행 전에 CRITERIA.md 에 적어 두고 결과를 보고 바꾸지 않았다.

- 프롬프트 12개. 함수 설명, 에러 진단, diff 설명, 설계 추천, 리팩터링, 테스트 실패, 성능, 개념 설명, 로그 분석, PR 리뷰, 설계 점검, git 충돌. 슬랙·메일·보고서처럼 스킬이 뜨는 요청은 뺐다.
- 조건 A(기준) 와 B(압축본 주입), 표본 2 → 생성 48회.
- 측정 셋. 훅 검사기 정규식, 같은 모델의 블라인드 쌍대 판정(순서 바꿔 2회), 종결어미 분포.

## 사실 정확도 (별도 검사)

판정 모델이 B 5건에 "사실 문제" 를 표시해서, 문체를 보지 않고 기술적 오류만 찾는 검사를 48건 전체에 따로 돌렸다.

| | 오류 있는 표본 | 오류 총계 | 심각 |
|---|---|---|---|
| A | 17 / 24 | 34 | 0 |
| B | 18 / 24 | 32 | 0 |

쌍으로 보면 B 가 더 많은 쌍 9, 더 적은 쌍 10, 같은 쌍 5 다. 압축본이 사실 정확도를 떨어뜨린다는 증거는 없다. 양쪽 다 과장이나 단정이 표본당 1.4건씩 나오는데, 이건 압축본과 무관한 모델의 기본 성질이다.

| 지표 | A (24) | B (24) |
|---|---|---|
| 훅 검사기 적중 | 2 (K3, K5) | 0 |
| 원시 패턴 합계 | 5 | 0 |
| ~할 수 있 | 11 | 6 |
| 굵게 `**` | 174 | 110 |
| 불릿 줄 | 163 | 136 |
| 줄표 삽입구 | 0 | 0 |
| 한글 글자 합계 | 14,749 | 15,231 |

A 에서 걸린 다섯 곳은 전부 진짜다. `GraphQL이 빛나는 조건은 이런 것들이다`, `4갈래 if/else`, `원인은 두 갈래 중 하나로`, `첫째, … 둘째, …`, `나중에 끝난 쪽이 이깁니다`. 같은 프롬프트의 B 에는 하나도 없다.

줄표가 두 조건 모두 0 인 점은 1차 실행과 다르다. 1차(사용자 훅 환경, 무효 출력 섞임)에서는 A 에 줄표 삽입구가 33개 있었다. 3차는 사용자 설정을 뺀 환경이라 기준선 자체가 깨끗해졌을 가능성이 있다. 아래 한계 참조.

## 종결어미

| | 합쇼체 우세 | 해요체 우세 | 해라체 우세 | 한 답변 안에 문체 섞임 |
|---|---|---|---|---|
| A | 5 | 2 | 17 | 11 / 24 |
| B | 2 | 3 | 19 | 6 / 24 |

프롬프트가 반말이라 A 도 해라체가 다수다. B 는 존댓말→해라체 전환 6쌍, 반대 4쌍으로 순증 2. 문체 섞임은 절반으로 줄었다("한 문체로 끝까지 간다" 규칙). 다만 1차 실행에서는 존댓말→해라체 7쌍, 반대 1쌍으로 쏠림이 컸다. 압축본이 해라체로 쓰여 있어 그 문체가 옮겨붙는 경향으로 본다. 배포 전에 압축본에 "높임은 사용자 말투를 따른다" 한 줄을 넣고 재확인할 일이다.

## 블라인드 판정 (3차)

같은 프롬프트의 A·B 답변을 순서를 바꿔 두 번씩 판정했다. 어느 쪽이 처리인지는 알려주지 않았다.

| | 쌍 수 |
|---|---|
| B 승 (두 순서 모두 B) | 21 |
| 무승부 (두 순서가 엇갈리거나 tie) | 3 (02-1, 06-2, 10-2) |
| A 승 | 0 |

12개 프롬프트 전부에서 B 가 이기거나 비겼다. 판정이 A 에서 반복해 지적한 것은 굵은 소제목과 불릿 첫머리 굵게(거의 전 표본), "결론부터." "정리하면" 같은 상투 문두, `것들`·`것` 형식명사, 영어 직역("화면을 얼린다", "배치는 굶습니다", "흔한 범인", "조용히 유실됩니다", "본문이 평평해집니다"), 첫째·둘째 병렬, 합니다체와 해요체 혼용이다. B 에서 지적한 것은 가벼운 의인화("타이머가 살아남아", "코드는 비용을 냅니다"), 구어 축약("~한 게", "~한 걸"), 불릿 머리말 굵게 정도다.

판정 근거 원문은 `judge/` 에, 집계는 `python3 aggregate.py` 로 다시 낼 수 있다.

## 실행 이력과 무효 처리

세 번 돌렸다. 앞의 둘은 환경 결함으로 버렸다.

1. **1차.** `--tools ""` 로 도구만 끔. 48건 중 24건이 가짜 Skill·AskUserQuestion·Bash 호출 텍스트로 끝났다. 원인 둘. 전역 CLAUDE.md 와 superpowers 주입이 "스킬을 먼저 로드하라" 고 지시하는데 도구가 없고, 사용자 전역 훅 `no-guess-gate` 의 Stop 훅이 도구 실행 0건인 턴에서 "확인이 필요", "것 같다", 파일명 같은 표현을 보면 턴 종료를 막고 실측을 요구한다. 훅 로그(events.log)에 판정 JSON 이 차단된 기록 6건이 남아 있다. 판정 4건 진행 중 중단.
2. **2차.** 시스템 프롬프트에 "도구와 스킬이 없다" 를 명시. 9건까지 표면상 정상이었으나 Stop 훅은 여전히 돌고 있었다(훅 로그에 2차 텍스트 존재). 중단.
3. **3차.** `--setting-sources ""` 로 사용자 settings.json 을 통째로 제외(훅·superpowers 주입 제거). 이러면 전역 CLAUDE.md 도 빠지므로 시스템 프롬프트에 원문을 붙여 되살렸다(인용 시험으로 확인). 모델·effort 는 사용자 설정값 `claude-fable-5-1`, `xhigh` 를 명시. `--settings` 주입은 이 플래그와 무관하게 적용됨을 마커 시험으로 확인. 48건 전부 유효(훅 로그에 3차 텍스트 없음).

## 한계

- **기준선 환경이 실제와 다르다.** 3차는 사용자 훅과 superpowers 주입을 뺐다. 실제 세션에는 둘 다 있다. 1차 A 에 줄표가 33개 있었고 3차 A 에는 0개인 것이 그 차이일 수 있다. 실제 환경에서의 효과는 3차보다 클 수도, 다를 수도 있다.
- **판정 모델이 생성 모델과 같다.** 양쪽 다 같은 모델 출력이라 자기 선호는 상쇄되지만, 모델이 좋아하는 문체가 사람이 좋아하는 문체와 같다는 보장은 없다.
- **정규식은 채팅 답변에서 거의 안 걸린다.** A 표본당 0.21. 이 검사기로는 답변 품질 회귀를 잡을 수 없다. "모든" 을 채택하면 답변 품질의 회귀 검사는 별도 수단이 필요하다.
- **단일 턴이다.** 긴 대화에서 주입 효과가 약해지는지는 못 봤다.
- **표본 2.** 프롬프트별 결과는 노이즈가 크다. 합계로만 읽어야 한다.
