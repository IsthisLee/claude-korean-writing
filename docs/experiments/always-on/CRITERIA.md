# 압축본 상시 주입 실험: 사전 등록 기준

작성 시각: 실행 전. 이 파일을 쓴 뒤에 생성·판정을 돌린다. 결과를 보고 기준을 바꾸지 않는다.

## 질문

SessionStart 훅으로 압축 규칙(inject.md)을 넣으면, 스킬이 뜨지 않는 보통의 채팅 답변에서 한국어가 더 자연스러워지는가. 자연스러워진다면 사실·격식·길이를 해치지 않는가.

## 조건

- A (기준): 사용자의 실제 환경 그대로. 전역 CLAUDE.md, superpowers 주입, 스킬 목록 포함. korean-writing 규칙 본문은 없음.
- B (처리): A + settings-B.json 의 SessionStart 훅으로 inject.md 주입.
- 공통: `claude -p --tools "" --no-session-persistence`, 기본 모델(claude-fable-5-1), cwd 는 스크래치패드(프로젝트 CLAUDE.md 없음). 도구를 끈 이유는 답변이 도구 호출 없이 산문으로만 나오게 하기 위해서다. 그래서 A 에서 on-demand 스킬 로드도 일어나지 않는다. 이 실험은 스킬이 뜨지 않는 답변만 다루므로 의도한 바다.

## 프롬프트

Claude Code 가 실제로 한국어 답변을 내는 장면 12개. 슬랙·메일·보고서처럼 스킬 트리거에 해당하는 요청은 뺀다(그건 이미 스킬이 맡는다). 각 프롬프트는 코드나 로그를 안에 담아 내용이 고정되게 한다. 그래야 판정이 내용이 아니라 문체를 비교한다.

## 표본

프롬프트 12 × 조건 2 × 표본 2 = 생성 48회.

## 측정

1. 정규식 (객관): plugin/hooks-handlers/posttooluse.sh 의 검사기를 답변 텍스트에 그대로 돌린다(.md Write 로 가장). K1~K8 적중 항목 수와, 검사기 임계 이하도 보기 위해 원시 패턴 횟수(줄표 삽입구, 추상 구조어, 것 구문, AI 관용구, 첫째·둘째, 승패 의인화, 사물 의인화, 번역투)를 따로 센다.
2. 블라인드 쌍대 판정 (LLM): 같은 프롬프트의 A 표본과 B 표본을 순서를 무작위로 섞어 판정 모델에 준다. 어느 쪽이 처리인지 알려주지 않는다. 판정 모델은 "더 자연스러운 한국어" 를 고르고(무승부 허용), 근거 패턴을 taxonomy ID 로 적고, 사실 누락·격식 변화·코드 훼손 여부를 따로 적는다. 순서 편향을 잡기 위해 각 쌍을 순서를 바꿔 2번 판정한다. 두 판정이 엇갈리면 무승부로 친다. 쌍은 (A1,B1), (A2,B2) 로 24쌍, 판정 48회.
3. 길이: 답변의 한글 글자 수. B/A 비율.
4. 비용: inject.md 의 실측 토큰(usage 차이), 생성 전체의 total_cost_usd 합.

## 판정 기준 (실행 전 확정)

주 기준 (둘 다 만족해야 "효과 있음"):
- P1. 블라인드 쌍대에서 무승부를 뺀 승률이 B ≥ 65%. 그리고 A 승이 B 승보다 많은 프롬프트가 3개 이하.
- P2. 정규식 원시 패턴 합계가 B 가 A 보다 낮다(합계 기준 30% 이상 감소). 단, A 의 합계가 표본당 0.5 미만이면 이 기준은 "측정 불가" 로 두고 P1 만 본다. 채팅 답변에서 정규식 패턴이 원래 거의 안 나오면 이 검사기로는 차이를 잴 수 없기 때문이다.

보호 기준 (하나라도 어기면 "효과 있음" 이어도 채택 보류):
- G1. 판정 모델이 "사실 누락 또는 왜곡" 을 표시한 B 표본이 24개 중 2개 이하.
- G2. 판정 모델이 "격식이 낮아짐(반말·구어체 유입)" 을 표시한 B 표본이 2개 이하.
- G3. 코드 블록·명령어·에러 문자열이 훼손된 B 표본이 0개.
- G4. 길이 비율 B/A 의 중앙값이 0.7~1.3.
- G5. inject.md 실측 토큰이 600 이하. (D2 기준 500 을 한 번의 조정으로 맞출 수 있는 범위)

결정 규칙:
- P1·P2 통과 + G1~G5 통과 → "모든" 채택 권고. 압축본 상시 주입을 플러그인에 넣는다.
- P1 통과, P2 측정 불가, G 통과 → 채택 권고하되 정규식 훅으로는 답변 품질을 회귀 검사할 수 없음을 문서에 적는다.
- P1 미달 → 채택 보류. 압축본을 고쳐 재실험하거나 "모든" 을 쓰지 않는다.
- G 위반 → 채택 보류. 어느 보호 기준이 깨졌는지와 원인을 보고한다.

## 알고 있는 한계

- 판정 모델과 생성 모델이 같다(claude-fable-5-1). A·B 모두 같은 모델 출력이라 자기 선호 편향은 양쪽에 같이 걸린다.
- 표본 2 는 작다. 결과가 기준선 근처면 "불확실" 로 보고한다.
- 정규식은 알려진 패턴만 잡는다. 정규식이 0 이어도 자연스럽다는 뜻은 아니다.
- -p 모드는 단일 턴이다. 긴 대화에서 주입 효과가 약해지는지는 이 실험으로 알 수 없다.

## 실행 전 수정 (2026-09-10 03:0x, 생성 시작 전)

- 공통 조건에 `--strict-mcp-config` 를 추가한다. 이유: `--tools ""` 만 붙이면 claude.ai 커넥터의 MCP 도구 정의 전체가 프롬프트에 실려 호출당 입력이 22만~30만 토큰(4~6달러)이었다. `--strict-mcp-config` 로 MCP 서버를 빼면 10,750 토큰(첫 호출 0.21달러, 이후 캐시 읽기)이다. 이 4회 시험 호출로 약 21달러가 나갔다. 두 조건 모두 같은 플래그를 쓰므로 비교에는 영향이 없다.
- 판정 프롬프트에서 "길이는 판정 기준이 아니다" 를 명시한다. 길이는 G4 에서 따로 본다.

## 1차 생성 무효 처리 (2026-09-10 05:2x, 판정 전)

1차 생성 48개 중 A 10개, B 7개가 답이 아니었다. `--tools ""` 로 도구를 껐는데 전역 CLAUDE.md 와 superpowers 주입은 "스킬을 먼저 로드하라" 고 지시하므로, 모델이 가짜 Skill·AskUserQuestion·Bash 호출을 텍스트로 쓰고 멈췄다. 한글 150자 미만 출력이 그 증거다 (예: 01_A_1 "korean-writing 스킬을 먼저 로드한 뒤 설명하겠습니다." 로 끝). 이런 쌍은 문체 비교가 성립하지 않는다.

조치: 두 조건 공통으로 `--append-system-prompt` 에 control.txt("이 세션에는 도구와 스킬이 없다. ... 바로 답한다") 를 넣고 48개를 다시 생성한다. 판정 기준(P1·P2·G1~G5)은 바꾸지 않는다. 1차 판정은 9개 진행 중 중단했고 결과는 쓰지 않는다. 1차 생성의 정규식 집계는 참고로만 보고에 남긴다 (raw_sum A 37 → B 9, 줄표 33 → 0. 단 무효 출력이 섞여 있다).

부수 관찰: A 조건에서 모델이 한국어 설명 프롬프트(01, 08, 10, 11)에 korean-writing 스킬을 로드하려 했다. 전역 CLAUDE.md 의 트리거를 "한국어 설명" 으로 넓게 읽은 것이다. 실제 세션에서는 스킬이 뜨므로 이 프롬프트들은 이미 스킬 규칙을 받는 경우가 있다.

## 2차 생성 무효 처리, 3차 환경 확정 (2026-09-10 05:5x, 판정 전)

2차 생성 9건은 표면상 정상이었지만 환경에 결함이 있어 중단했다. 사용자 전역 설정의 `no-guess-gate` Stop 훅이 도구 실행 0건인 턴에서 "확인이 필요", "것 같다", "없다" 류 표현을 보면 exit 2 로 턴 종료를 막고 실측을 요구한다. 도구가 없는 헤드리스 세션은 이를 만족시킬 수 없어 모델이 재시도 끝에 가짜 도구 호출을 쓴다. 1차 판정 4건 중 2건이 이 훅 때문에 AskUserQuestion 흉내로 끝난 것을 확인했다(judge_run1/01_2_o1.json). 프롬프트에 파일명이 있으면 R2b 규칙이 걸리므로 12개 프롬프트 대부분이 영향권이다. 이 훅은 문체와 무관한 교란이다.

3차 환경 (두 조건 공통):
- `--setting-sources ""` 로 사용자 settings.json 을 전부 제외한다. no-guess-gate 훅과 superpowers SessionStart 주입이 같이 빠진다. `--settings settings-B.json` 은 이 플래그와 무관하게 적용됨을 마커 시험으로 확인했다.
- 모델과 effort 는 사용자 설정값을 명시한다: `--model claude-fable-5-1 --effort xhigh`. 1차·2차도 modelUsage 상 같은 모델이었다.
- `--append-system-prompt control.txt` 는 유지한다.
- 전역 CLAUDE.md 로드 여부는 별도 시험으로 기록한다.

판정 기준은 그대로다. 2차 생성 9건은 쓰지 않는다.
