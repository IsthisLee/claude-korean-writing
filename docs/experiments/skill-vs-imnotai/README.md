# 스킬 대 im-not-ai

`korean-writing` 스킬로 처음부터 쓴 글이 im-not-ai 로 사후 윤문한 글만큼 자연스러운지 재는 자리입니다. 이 플러그인의 목표가 "스킬 품질이 im-not-ai 수준이 되거나 그보다 높은 것" 이라 그 목표를 그대로 실험으로 옮겼습니다.

## 왜 정규식으로는 안 되나

2026-09-10 실측에서 규칙을 늘려 AI 티 표지를 표본당 1.95에서 0.25로 줄인 판이 블라인드 쌍대 판정에서는 옛 판을 이기지 못했습니다(5승 6패). 판정자가 지적한 것은 표지가 아니라 리듬이었고, 재 보니 문장 길이 표준편차가 16.28에서 12.93으로 떨어져 있었습니다. 규칙을 지키려고 문장을 짧게 끊은 결과입니다. 표지 개수는 규칙이 먹혔는지는 알려 주지만 글이 나아졌는지는 알려 주지 않습니다.

## 어떻게 도나

```bash
docs/experiments/skill-vs-imnotai/run.sh                    # 기본 프롬프트 넷
docs/experiments/skill-vs-imnotai/run.sh /tmp/out 01 L1 L4  # 출력 위치와 프롬프트 지정
```

프롬프트마다 두 글을 만듭니다. 하나는 `SKILL.md` 를 시스템 프롬프트로 붙여 처음부터 쓴 것이고, 다른 하나는 규칙 없이 쓴 뒤 im-not-ai 파이프라인으로 윤문한 것입니다. 어느 쪽이 어느 조건인지 모르는 판정자에게 순서를 바꿔 두 번 묻고, 두 번 같은 답이 나온 쌍만 승패로 셉니다. 스킬이 진 쌍이 이긴 쌍보다 많으면 종료 코드 1입니다.

윤문 경로는 글 길이에 맞춥니다. 단문(`01`~`08`, 400~600자)은 Fast Path 한 콜이고 장문(`L1`~`L6`, 1,500자)은 정밀 3콜(진단·윤문·마무리)입니다. 결합 입력은 저장소의 `plugin/scripts/prepare_monolith_input.py` 가 만들고 시스템 프롬프트는 `plugin/agents/` 의 에이전트 정의와 규칙집 원문입니다. 도구가 없는 세션이라 파일 입출력만 표준입출력으로 바꿨습니다.

환경변수로 모델을 바꿉니다. `KW_MODEL` 은 생성과 윤문, `KW_JUDGE` 는 판정입니다. 둘 다 기본값이 `claude-opus-5` 입니다. 판정자를 생성자와 다른 모델로 두면 한쪽으로 기우는지 볼 수 있습니다.

## 언제 도나

규칙을 고쳤고 릴리스가 가까울 때 사람이 한 번 돌립니다. LLM 을 부르므로 CI 에는 넣지 않습니다. 프롬프트 넷이면 생성 여덟 번, 윤문 최대 열네 번, 판정 여덟 번입니다.

## 먼저 읽을 것

**병렬로 돌릴 때 `claude` 호출에 `< /dev/null` 을 붙입니다.** 붙이지 않으면 작업 목록 stdin 을 물어 마지막 묶음이 통째로 빈 출력을 냅니다. 실측에서 24건 중 4건이 그렇게 죽었고, 그 빈 값을 중앙값에 넣어 분량 결론을 한 번 잘못 냈습니다.

**판정 출력이 JSON 이 아니면 계정 사용량부터 봅니다.** 크레딧이 떨어지면 안내 문구가 JSON 자리에 들어옵니다. 실측에서 판정 96회 중 34회가 그렇게 실패했습니다.

## 결과는 어디에

`EVALUATION.md` 의 C7·C9·C10 입니다. 1차 판정은 41쌍에서 스킬 22승 im-not-ai 19승으로 우열을 말할 수 없는 자리였습니다(단측 p=0.378). 진 쌍의 이유를 읽어 말미의 분량 보고와 소제목과 문단 끝 리듬 셋을 규칙으로 넣고 다시 붙인 2차 판정이 56쌍에서 49승 0패입니다. 지금 저장소에 있는 `SKILL.md` 가 그 판입니다.
