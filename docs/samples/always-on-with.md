이 함수는 값이 바뀔 때마다 즉시 반영하지 않고, 마지막 변경 후 `delay` 밀리초 동안 값이 더 이상 바뀌지 않을 때만 반영하는 디바운스 훅입니다. 예를 들어 검색창에 타이핑할 때마다 API를 호출하는 대신, 타이핑을 멈추고 일정 시간이 지난 뒤에야 요청을 보내고 싶을 때 씁니다.

동작 흐름은 이렇습니다.

1. `value`나 `delay`가 바뀌면 `useEffect`가 다시 실행되고, `delay` 뒤에 `debounced` 상태를 새 값으로 갱신하는 타이머를 하나 겁니다.
2. 그 사이에 `value`가 또 바뀌면 이펙트가 다시 실행되면서 새 타이머를 겁니다.

여기서 cleanup(`return () => clearTimeout(id)`)이 없으면 문제가 생깁니다. 이전 이펙트가 걸어둔 타이머가 그대로 살아 있다가, 새 타이머보다 먼저 만료되어 **이미 지나간 옛날 값**으로 `setDebounced`를 호출해버립니다.

구체적으로 사용자가 `t=0`에 "a", `t=100`에 "ab"를 입력하고 `delay=300`이라면,

- cleanup이 없을 때: `t=300`에 옛 타이머가 먼저 실행되어 `debounced`가 "a"로 바뀌었다가, `t=400`에 다시 "ab"로 바뀝니다. 중간에 "a"라는, 사용자가 이미 지나쳐 버린 값이 잠깐 반영되면서 디바운스의 목적(마지막 값 하나만 반영)이 깨집니다.
- cleanup이 있을 때: `value`가 바뀔 때마다 이전 타이머가 즉시 취소되므로, 실제로 실행되는 타이머는 마지막에 걸린 것 하나뿐입니다. 그래서 사용자가 입력을 멈추고 300ms가 지난 시점에 최종 값만 딱 한 번 반영됩니다.

같은 이유로 컴포넌트가 언마운트될 때도 cleanup이 실행되어 남아 있는 타이머를 정리하므로, 이미 사라진 컴포넌트를 위해 불필요한 상태 갱신이 예약된 채로 남는 상황도 막아줍니다.
