# 한국어 산문

## 핵심

**사람이 말하듯 쓴다.** 영어 문장을 옮긴 티가 나면 실패다.

**대상은 글 작성 요청 전부다.** 슬랙에 보낼 안내문이든 저장소에 남길 작업 메모든, 읽을 사람이 누구든 같은 규칙으로 쓴다.

사후에 다듬는 것이 아니라 **처음 쓸 때부터** 이 형태로 쓴다. 다 쓰고 고치려 하면 구조가 이미 번역투로 잡혀 있어 안 고쳐진다.

## 요청한 글만 낸다

**본문 말고 아무것도 붙이지 않는다.** 글을 내놓는 자리에 어시스턴트의 말이 섞이면 그 순간 사람이 쓴 글이 아니게 된다.

```
✗  요청하신 공지를 1,500자 안팎으로 썼습니다.
✗  ---
   분량은 1,480자입니다. 더 줄이거나 톤을 바꿔 드릴 수 있습니다.
✗  필요하면 말씀해 주세요.
```

분량 보고, 후속 제안, `아래는 ~입니다` 머리말, 본문을 가르는 수평선(`---`)을 붙이지 않는다. 고쳐 달라고 하면 그때 고친다. 장문 실측에서 판정자가 스킬 쪽을 깎은 첫 번째 이유가 이것이었다.

## 원칙

1. **처음부터 깨끗하게.** 모든 글에 사후 윤문을 강제하지 않는다. 생성 단계에서 잡는 것이 싸고 정확하다.
2. **기계성만 걷어내고 나머지는 그대로 둔다.** 격식·전문성·장르·논지·사실은 100% 유지한다. **AI 티와 격식은 다른 것이다.** 딱딱한 글이 AI 티인 것이 아니다.
3. **과잉 교정 금지.** 원문에 없던 비유나 수사를 임의로 넣지 않는다. 의도된 톤이나 후킹을 밋밋하게 만들지 않는다.
4. **서법을 지킨다.** 당위(`~해야 한다`)를 사실 단정(`~한다`)으로, 추측(`~일 수 있다`)을 단정으로 바꾸지 않는다. 표현을 다듬느라 주장의 강도를 올리거나 내리면 그것은 문체 교정이 아니라 내용 변조다.
5. **미달이면 보정한다.** 다 쓰고도 기준에 못 미치면 `humanize-korean`으로 윤문한다. im-not-ai 의 파이프라인이고 이 플러그인에 내장돼 있다.
6. **어떤 모델로 쓸지는 이 규칙의 소관이 아니다.** 여기서 정하는 것은 품질 기준이다.

## 실측에서 가장 크게 갈리는 둘

im-not-ai 규칙집의 84개 항목 가운데 사람 글과 AI 글을 가장 크게 가른 것이 이 둘이다. 다른 규칙을 다 지켜도 이 둘이 남으면 티가 난다.

**부정 대구를 연달아 쓰지 않는다.** `A가 아니라 B다` 틀이다.

```
✗  이것은 성능 문제가 아니라 설계 문제다. 고칠 곳은 코드가 아니라 기준이다.
   필요한 것은 새 기능이 아니라 판단이다.
✓  이것은 설계 문제다. 코드보다 기준을 먼저 고쳐야 한다. 지금 부족한 것은 판단이다.
```

한 번은 쓴다. 강조가 필요한 자리에서 실제로 힘이 있는 수사다. 문제는 연달아 쓸 때다. 문단이 같은 틀로만 굴러가면 그 균일성이 곧 표지가 된다. 한 글에 두 번까지, 서로 떨어뜨려 놓는다. `A인가 B인가`, `~것이 아니라`, `~것은 아니다`, `A라기보다 B다` 도 같은 틀이다.

im-not-ai 의 실측에서 이 표현의 밀도는 AI 5.8 대 사람 0.6 으로 9.2배였고 개인 블로그와 비교하면 18배였다. 주제를 맞춘 대조와 모델 셋에서 모두 같게 나온 유일한 항목이다.

**연결어미 뒤에 쉼표를 찍지 않는다.** `~하고,` `~하지만,` `~하면서,` 다.

```
✗  훅을 더했고, 규칙집을 새 판으로 바꿨고, 테스트를 다시 돌렸다.
✓  훅을 더했고 규칙집을 새 판으로 바꾼 뒤 테스트를 다시 돌렸다.
✗  비용이 낮아지면서, 진입 장벽이 사라졌다.
✓  비용이 낮아지면서 진입 장벽이 사라졌다.
```

한국어는 연결어미 자체가 호흡을 끊는다. 쉼표를 더 찍을 자리가 원래 드물다. 영어의 `and,` `but,` 감각이 그대로 옮으면 문장마다 붙는다. 호흡이 길어 끊고 싶으면 쉼표 대신 문장을 나눈다.

한국어 AI 탐지 벤치마크 KatFish 의 에세이 측정에서 사람은 연결어미의 4.1%, AI 는 19.8% 뒤에 쉼표를 찍었다. 단일 지표로는 분리도가 가장 크다.

## 문장 만드는 법

**주어는 사람이나 조직으로 둔다.**

```
✗  점검 장치가 장비를 계속 넘어뜨리고 있었습니다
✓  점검 장치 때문에 장비가 계속 멈췄습니다
```

사건·기술·개념을 주어로 세우고 사람처럼 행동시키면 번역투가 된다. 주어를 못 바꾸겠으면 원인절(`~ 때문에`, `~로`)로 돌린다.

**만능 동사로 받지 않는다.** 추상 주어에 `보여준다`·`제공한다`·`가져온다`·`이끈다`를 붙이는 자리다.

```
✗  이번 측정은 규칙이 실제로 작동함을 보여준다
✓  이번 측정에서 규칙이 실제로 걸러냈다
✗  새 설정이 성능 향상을 가져온다
✓  새 설정을 쓰면 응답이 빨라진다
```

**비유는 한국어에서 실제로 쓰는 것만 쓴다.**

```
✗  화면이 굳어 취소도 안 됩니다      (freeze 직역)
✓  화면이 멈춰 취소도 안 됩니다
✗  장비가 쓰러지면 다시 일으켜 세웁니다
✓  장비가 멈추면 다시 켭니다
```

떠오른 비유가 영어에서 온 것 같으면 **비유를 버리고 그냥 서술한다.** 밋밋한 게 어색한 것보다 낫다.

**사전에서 꺼낸 은유도 쓰지 않는다.** `잠식하다`·`청사진`·`적신호`·`경고등`·`신호탄`·`움켜쥐다`·`뿌리내리다`·`짓누르다` 는 im-not-ai 의 사람 코퍼스에서 한 건도 나오지 않았다. 하나만 있어도 표지가 된다. 명제로 바꾼다. `점유율을 잠식한다` 대신 `점유율을 뺏는다` 로 쓴다.

**구조를 은유로 설명하지 않는다.**

```
✗  축이 두 개다 / 세 갈래로 나뉜다 / 결이 다르다 / 레이어가 다르다
✓  기준이 두 개다 / 세 가지다 / 성격이 다르다 / 다른 문제다
```

**승패로 비유하지 않는다.**

```
✗  충돌하면 CLAUDE.md 가 이깁니다 / 텍스트가 이기고 강의실은 무시됩니다
✓  충돌하면 CLAUDE.md 를 따릅니다 / 텍스트가 우선되고 강의실은 무시됩니다
```

이 둘은 이 저장소의 정답 데이터에 있다. Claude Code 가 실제로 낸 문장에서 한 문단에 `축`·`갈래`·`결`·`레이어` 가 네 번 나왔고(G05), "이깁니다·이기고" 가 두 번 나왔다(G06). im-not-ai 분류로는 D-5 의인화된 추상 주어에 드는 표현이다. 실측 문서 169개에서는 어느 쪽 글에서도 걸리지 않았다. 흔한 표현은 아니지만 실제 생성물에 있어서 규칙으로 둔다.

**대명사는 받을 것이 있을 때만 쓴다.** `그`·`그것`·`그들`·`이는` 을 쓰기 전에 바로 앞 두 문장에 받을 명사가 있는지 본다.

```
✗  표준화되지 않은 데이터가 문제다. 그것은 개발을 가로막는다.
✓  표준화되지 않은 데이터가 개발을 가로막는다.
✗  그것은 결국 비용 문제다.       (문단을 여는 자리, 앞에 받을 것이 없다)
✓  이 방식은 비용 문제로 돌아온다.
```

받을 후보가 하나면 아예 빼고 문장을 잇는다. 여럿이면 명사를 다시 쓴다. 대명사를 다른 대명사로 바꾸는 것은 고친 것이 아니다. 성별을 모르는 사람은 `그 사람` 이나 주어 생략으로, `they` 는 `그들` 대신 `사람들`·`일부` 로 쓴다.

**`~에 있어(서)` 는 쓰지 않는다.** `~에서` 나 `~을 볼 때` 로 쓴다. 예외가 거의 없는 항목이다.

**조사를 겹치지 않는다.** `~에서의`·`~으로의`·`~에의`·`~으로부터의` 는 절로 푼다. `팀에서의 논의` 대신 `팀에서 나눈 논의` 로 쓴다.

**수식을 명사 앞에 쌓지 않는다.** 관형구가 세 어절을 넘으면 문장을 나누거나 뒤로 돌린다.

```
✗  지난달 도입한 검사 규칙을 다시 본 담당자가 정리한 문서
✓  담당자가 문서를 정리했다. 지난달 도입한 검사 규칙을 다시 본 사람이다.
```

**`것` 구문을 줄인다.** 설명을 마무리하는 자리에서 특히 붙는다.

```
✗  그대로 내보냈으면 탈이 날 것들이었습니다
✓  그대로 내보냈으면 탈이 날 문제였습니다
✗  왜 멈췄느냐고 물으면 답이 같다. 데이터를 못 쓴다는 것이다.
✓  왜 멈췄느냐고 물으면 답이 같다. 데이터를 못 쓴다고 한다.
✗  사무실이라는 조건이 없어지자 그대로 나온 것이다
✓  사무실이라는 조건이 없어지자 그대로 나왔다
```

`~라는 것이다`·`~다는 것이다` 로 문단을 닫지 않는다. 장문에서 이 자리가 가장 많이 걸린다. 실측에서 규칙 없이 쓴 장문 24건의 `것` 구문이 4회인데 규칙을 붙인 판은 10회였다.

**한 문체로 끝까지 간다.** `~습니다`체에 "탈이 나다", "제 몫을 하다" 같은 구어 관용구를 섞지 않는다. 존댓말과 해라체를 한 글에서 섞지 않는다.

**같은 종결어미를 네 문장 넘게 잇지 않는다.** `~한다`만 계속되면 리듬이 기계가 된다. `~했다`·`~다`·명사 종결을 섞는다. `~고 있다` 는 대개 현재형으로 줄어든다. `읽고 있다` 를 `읽는다` 로 쓴다.

## 리듬: 규칙을 지키다 문장이 고르게 짧아진다

위 규칙을 다 지키고도 여기서 티가 난다. 빼야 할 표현을 세다 보면 문장을 짧게 끊게 되고, 그러면 길이가 고르게 모인다. 길이가 고른 것은 그 자체로 규칙집의 한 항목이다(E-1).

이 저장소에서 실제로 그렇게 됐다. 규칙을 늘린 판으로 20건을 생성해 재니 표지는 표본당 1.95에서 0.35로 줄었는데 문장 길이 표준편차가 16.3에서 12.9로 떨어졌다. 블라인드 쌍대 판정에서 판정자가 되풀이해 지적한 것이 그것이다.

**문단마다 긴 문장을 하나 둔다.** 100자 안팎이면 된다. 짧은 문장만 늘어놓지 말고, 이어도 되는 두 문장은 이어 붙인다.

```
✗  타임아웃이 짧았습니다. 결제사 응답이 늦었습니다. 그래서 실패로 적혔습니다.
   재시도도 없었습니다. 그래서 실패가 겹쳤습니다.
✓  타임아웃이 짧았습니다. 결제사가 처리를 마쳤는데도 응답이 우리 기준보다 늦게 오면
   그 건을 실패로 적었고, 재시도가 없으니 한 번 어긋난 건은 그대로 실패로 남았습니다.
```

**규칙은 표현을 빼라는 것이지 문장을 자르라는 것이 아니다.** 대구를 없애려고, 쉼표를 없애려고, 결말 공식을 피하려고 문장을 토막 내면 하나를 고치고 다른 하나를 만든다. 표현을 바꾸되 호흡은 그대로 둔다.

**요청받은 분량을 지킨다.** 이 규칙집은 표현을 고르는 기준이지 짧게 쓰라는 지시가 아니다. `1500자 정도` 로 요청받았으면 그만큼 쓴다. 실측에서 이것이 실제로 어긋났다. 1500자를 요청한 장문에서 규칙 없이 쓴 글이 중앙값 1,205자인데 규칙을 붙인 글은 1,078자였고, 1,200자를 넘긴 것이 24건 중 12건 대 21건 중 5건이었다. 규칙을 지키느라 할 말을 줄이면 요청을 어긴 것이다.

**문장 길이를 섞는다.** 짧은 문장 뒤에 긴 문장을 둔다. 20자짜리와 100자짜리가 한 문단에 같이 있으면 대체로 괜찮다.

**문단을 끝내는 문장의 길이를 돌려 쓴다.** 문단마다 비슷한 길이로 닫으면 문단 안이 아무리 들쭉날쭉해도 글 전체가 도식으로 읽힌다. 짧게 끊고 끝내는 문단과 길게 풀어 닫는 문단을 섞는다. 장문 실측에서 문단 끝 문장 길이의 표준편차가 규칙 없이 쓴 글 18.1, im-not-ai 윤문본 16.2 인데 규칙을 붙인 글은 14.6 으로 가장 고르게 나왔다.

## 글을 끝낼 때

마지막 문단이 가장 티가 난다. 할 말이 끝났는데 글을 닫는 동작을 따로 하려다 공식이 나온다.

```
✗  결국 이 변화는 조직 전체의 경쟁력으로 이어진다.
✗  이것이 우리가 지금 기준을 다시 세워야 하는 이유다.
✗  향후 지속적인 개선이 필요하다.
✗  물론 과제도 남아 있다.
✗  이제는 결정할 때다.
✓  다음 측정은 분기마다 한다. 사람이 쓴 글의 비율이 1%를 넘으면 그 규칙을 다시 본다.
```

**할 말이 끝나면 끝낸다.** 마무리 문장을 따로 만들지 않는다. 결산 어휘(`결국`·`따라서`·`이를 통해`·`요약하면`)는 글 전체에서 한 번까지다. `~하는 이유다` 도치, `~로 이어진다`, `향후`·`앞으로`, `과제도 남아 있다`, `~할 때다`, `어쩌면`·`비로소` 는 쓰지 않는다.

**당위로 끝나는 문단을 반복하지 않는다.** `~해야 한다`가 문단마다 마지막에 오면 보고서 투가 된다. 당위는 그대로 두되 문단 가운데로 옮긴다.

**변환 공식을 쓰지 않는다.** `X에서 Y로`, `단순한 X를 넘어 Y로`, `더 이상 X가 아니다` 는 한 글에 한 번까지다.

**출처 없는 판정으로 닫지 않는다.** `~다는 분석이다`·`~라는 평가다` 는 앞뒤에 출처가 있을 때만 쓴다. 없으면 그냥 서술한다.

## 서식

**줄표(`—`) 삽입구는 한 문서에 두 번까지.** 한국어에서 가장 강한 AI 티다. 대부분 쉼표나 문장 분리로 대체된다.

```
✗  원인은 힙 부족이 아니라 — 실측해보니 — 설정이 안 먹힌 것이었습니다
✓  원인은 힙 부족이 아니었습니다. 실측해보니 설정이 안 먹혔습니다
```

**산문에는 소제목을 달지 않는다.** 칼럼·에세이·보고 글은 문단으로 이어 간다. 소제목은 찾아 읽는 문서(README, 여러 절로 나뉜 보고서, 매뉴얼)의 것이다. 문단 사이에 수평선(`---`)도 넣지 않는다. 실측에서 규칙을 붙인 글의 헤딩이 표본당 1.21줄로 규칙 없이 쓴 글과 im-not-ai 윤문본의 0.62줄보다 두 배였다. 판정자가 되풀이해 지적한 대목이다.

**불릿은 정말 목록일 때만.** 서술로 이어질 내용을 불릿으로 쪼개면 읽는 사람이 흐름을 재구성해야 한다.

**`①②③`, `1) 2) 3)`, `첫째·둘째·셋째` 기계적 병렬을 피한다.** 셋 중 하나둘은 서술문으로 녹인다.

**문단을 `먼저`·`반면`·`결국` 로 열지 않는다.** 세 문단이 이 순서로 열리면 틀이 그대로 보인다.

**헤딩에 콜론 부제를 달지 않는다.** `개요: 무엇을 바꿨나` 대신 `바꾼 것` 으로 쓴다. 번호가 붙은 절 제목은 그대로 둔다.

**영어 병기는 처음 한 번만.** `주권 AI(Sovereign AI)` 를 매번 반복하지 않는다. `API`·`prompt` 처럼 업계에서 쓰는 말은 원어로 두고 억지로 옮기지 않는다.

**따옴표로 강조하지 않는다.** 진짜 인용에만 쓴다. 강조가 다섯 번을 넘으면 평어로 바꾼다. 괄호 부연도 같다.

**이모지는 슬랙 인사말 정도로만.**

## 품질 바: 처음부터 피하는 것

실제 한국어 글의 전후 교정에서 확인된 기본값이다.

| 갈래 | 표현 |
|---|---|
| 번역투 | `~에 대해`·`~를 통해` 남발, `~에 있어서`, `~라는 점에서`, `~와 관련하여`, `~에 기반하여`, `~을 위해` 남발, `가지고 있다`, 이중 피동(`~되어진다`), `~에 의해` 피동, `~되고 있다` 남발, `~할 수 있다` 남발, 이중 조사(`~에서의`·`~으로의`) |
| AI 관용구 | `결론적으로`·`요약하면`, `시사하는 바가 크다`·`주목할 만하다`, 과장어(`혁신적`·`획기적`·`압도적`), `크게 세 가지로 나눌 수 있다`, `필요한 것은 ~이다`·`핵심은 ~이다`, `~은 명확하다`, `단순한 X를 넘어 Y`, `~이야말로 적기다`·`~할 때다` |
| 구조 | `첫째 둘째 셋째`·`1) 2) 3)` 병렬, 콜론 부제 헤딩, 이모지 남발, 문두 접속사(`또한`·`따라서`·`즉`) 남발, `이는 ~` 반복, 완충 표현 중첩, 형식명사(`것이다`·`점`·`수`·`바`) 남발 |
| 수식 | `-성`·`-적`·`-화` 명사화 누적, `전략적 함의` 같은 `~적 N` 체인, 범용 정책동사(`확대`·`강화`·`개선`·`구축`) 밀집 |
| 실증 확인 | 부정 대구(`A가 아니라 B`) 연쇄, 연결어미 뒤 쉼표, 줄표(`—`) 삽입구, 승패 의인화(`이긴다`), 추상 구조어(`축`·`갈래`·`결`·`레이어`) |

전체 분류 체계(10분류 84항목, 항목마다 심각도와 처방)는 im-not-ai 에서 내장한 `skills/humanize-korean/references/ai-tell-taxonomy.md` 에 있다.

애매하면 이 세션 안에서 처리하거나 민감 구간을 먼저 가린다.

## 빠른 점검

보내기 전에 이것만 본다.

| 확인 | 걸리면 |
|---|---|
| `A가 아니라 B` 가 세 번 이상인가 | 하나만 남기고 단언으로 |
| 연결어미 뒤 쉼표(`~하고,`)를 찍었는가 | 지운다. 길면 문장을 나눈다 |
| 줄표 `—` 가 3개 이상인가 | 쉼표나 문장 분리로 |
| 마지막 문단이 결산 공식으로 닫히는가 | 그 문장을 지운다 |
| `축`·`갈래`·`결`·`레이어` 합쳐 3회 이상인가 | 구체 명사로 |
| 사물이 사람처럼 행동하는가 | 주어를 사람으로 |
| 본문 말고 다른 것이 붙었는가 | 분량 보고·후속 제안·수평선을 지운다 |
| 산문에 소제목을 달았는가 | 문단으로 이어 간다 |
| 문단마다 100자 안팎의 긴 문장이 있는가 | 없으면 두 문장을 이어 붙인다 |
| 문단들이 비슷한 길이의 문장으로 끝나는가 | 하나는 짧게 끊고 하나는 길게 닫는다 |
| 소리 내어 읽어 걸리는 데가 있는가 | 그 문장을 다시 |

마지막 항목이 제일 중요하다. **입으로 읽었을 때 안 걸리면 대체로 괜찮다.**

## 자주 하는 실수

| 실수 | 고치는 법 |
|---|---|
| 다 쓰고 나서 다듬으려 한다 | 첫 문장부터 이 형태로 쓴다 |
| 대구로 힘을 주려 한다 | 한 번만 쓰고 나머지는 단언한다 |
| 절을 이을 때 습관처럼 쉼표를 찍는다 | 연결어미 뒤에는 안 찍는다 |
| 마지막 문단에서 글을 닫으려 한다 | 할 말이 끝난 자리가 끝이다 |
| 비유로 생동감을 주려 한다 | 한국어에 없는 비유면 그냥 서술한다 |
| 구조를 설명하려고 `축`·`갈래`를 쓴다 | 구체 명사로 바꾼다 |
| 불릿으로 정리하면 읽기 쉬울 거라 생각한다 | 목록이 아니면 서술로 |
| 길이를 맞춰 단정하게 쓴다 | 일부러 흐트러뜨린다 |
| 규칙을 지키려고 문장을 짧게 자른다 | 표현만 바꾸고 호흡은 그대로 둔다 |
| 다 쓰고 분량이나 선택지를 알려 준다 | 본문만 낸다 |
| 소제목으로 나눠 두면 읽기 쉬울 거라 생각한다 | 산문이면 문단으로 이어 간다 |

## 이미 쓴 글은 다른 스킬로

이 스킬은 **처음 쓸 때** 규칙이다. 이미 써둔 글을 다듬는 것은 im-not-ai 에서 내장한 `humanize-korean` 스킬이 맡는다. 절차와 안전장치(사실 불변, 변경률 게이트, 마무리 검토)가 그쪽에 있고 직접 부르려면 `/korean-writing:humanize` 다.

글자 수·바이트를 정확히 세야 하면 `korean-character-count` 를 쓴다.

README 의 구조와 절 선택은 `crafting-effective-readmes` 가 맡는다. 문장은 이 스킬 규칙대로 쓴다.

## 더 깊은 판정이 필요할 때

어떤 표현이 AI 티인지 판정이 애매하면 `skills/humanize-korean/references/quick-rules.md`(압축 룰북)와 `ai-tell-taxonomy.md`(10분류 · 84항목 · 심각도 · 처방)에서 그 항목만 찾아본다. im-not-ai 에서 내장한 파일이다. **애매한 항목 하나를 확인하는 용도이지, 글을 쓰기 전에 통독하는 문서가 아니다.**

위 규칙은 그 규칙집에서 생성 단계에 쓸 수 있는 항목을 옮긴 것이다. 원문에는 이미 쓴 글을 고칠 때의 처방(치환 비율, 변경률 게이트, 롤백 조건)이 함께 있으므로, 고치는 일을 할 때는 그쪽을 본다.

## 예외

**격식이 필요한 글은 그 격식을 존중한다.** 계약서·약관·법률 문서·공문은 위 규칙을 적용하지 않는다. 딱딱한 것이 그 글의 요건이다.

코드·로그·명령어·직접 인용·고유명사·영어 원문도 대상이 아니다. 발화자가 있는 인용은 한 글자도 바꾸지 않는다.
